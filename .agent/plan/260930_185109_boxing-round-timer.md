# Boxing Round Timer (Timer tab, Training-screen clock, voice)

## Context

The app has a combo trainer with in-app voice ("combo 3", "combo next"). README's "Not in v1"
lists round/rest timers and sound cues. This plan adds them.

The user asked for:
- a separate bottom tab with editable defaults (round time, start delay, rest, …);
- voice control, e.g. "set 2 minutes countdown", which runs a 10 s lead-in, then the start bell,
  then the end bell;
- a clock on the combo (Training) screen. It should float in the center, show only while a
  timer runs and disappear when it's done, keep the current combo visible, and have its
  position configurable in settings.

Wireframes: `260930_185109_boxing-round-timer.wireframes.html`, next to this file. The
letters below refer to its frames:
- A, A2, B, B2–B4, C: setup;
- D, E, E2, F–I: run;
- J–N: Training clock.

## Scope

In (v1):
- **Timer tab** (Training | Timer | Favorites):
  - setup (A–C): presets, round time, rest, rounds (1–20 or ∞), start delay, cues, display,
    "Test sounds";
  - run screens: lead-in, round, warning window, rest, paused, done (D–I).
- **Presets.** Built-in: Muay Thai 5×3:00/2:00, Boxing 12×3:00/1:00, MMA 3×5:00/1:00,
  Tabata 8×0:20/0:10, Bag 6×2:00/0:30. Users can also save their own. Editing any value turns the
  selection into "Custom".
- **Cues:**
  - start bell (1 ring) and end bell (3 rings);
  - round-end warning (clap, off/5/10/15/30 s);
  - rest-end warning (double beep);
  - 3-2-1 beeps;
  - TTS announcements ("Round 2", "Last round", "Rest", "Ten seconds", "Time");
  - optional vibrate on bells.
  - All sounds are generated by our own script, with no downloads.
- **Quick countdown.** "set 2 minutes countdown" runs one round of N with the lead-in and starts
  right away. It never changes saved settings.
- **Training-screen clock (J–N):**
  - It's hidden until a timer starts, and fades out 2 s after the final bell (at once on stop).
  - Position setting: **Center** (default, an overlay with the current-combo card under the
    clock), **Top** band, **Bottom** band, or **Off**.
  - A header "timer pill" starts the saved workout from Training.
- **Tab label** shows the live time on the Timer tab while running ("R2 · 1:12").
- **Voice.** A timer grammar on the shared mic, which works from every tab (wireframe
  section 6).
- **Screen** kept awake while the timer is running or paused.
- **Persistence.** Settings, custom presets and clock position are saved in AsyncStorage.

Out (v2 candidates):
- Bells while the phone is locked or the app is in the background. v1 is foreground-only with
  the screen kept awake, as agreed.
- Rounds driving combos (auto "combo next" at each new round).
- Workout history and stats.
- Custom or imported sounds.
- Pyramid or mixed-length intervals.
- A draggable clock.
- iOS polish. The app is Android-first.

## Approach

### Engine: pure and wall-clock based (`utils/roundTimer.js`)
- `buildSegments(config)` returns
  `[prep, work 1, rest 1, …, work N]`, with no rest after the last round. ∞ is capped at
  99 rounds internally.
- `buildCues(segments, config)` returns a sorted list of `{ atMs, sound?, say?, vibrate? }`
  (timeline in wireframe section 4).
  - The round-end warning is skipped when the round is shorter than twice the warning window.
  - TTS lines never contain a voice trigger word.
- `positionAt(segments, elapsedMs)` returns the segment index, phase, round, `remainingMs`,
  phase progress, total time left and next-segment label.
- Elapsed time is `now − startedAt − pausedTotal`. It never counts ticks: `useSession`'s 1 s
  `setInterval` countdown drifts, and that must not happen here.

### Run state (`hooks/useRoundTimer.js` + `TimerContext`)
- `status`: `idle | running | paused | done`.
- The run takes a frozen snapshot of its config, so editing settings mid-run can't affect it.
- `kind: 'workout' | 'countdown'` drives the labels ("ROUND 2 OF 5" vs "COUNTDOWN").
- API: `start(override?)`, `pause`, `resume`, `skip`, `restartPhase`, `stop`, `dismissDone`.
- UI tick: 100 ms while a dial is visible, 250 ms otherwise. Cues fire from a dedicated
  `setTimeout` aimed at the next cue's `atMs`, which is re-armed after each fire and on
  pause/resume, so bells stay tight.
- On return from the background, cues more than about 1.5 s late are dropped silently.
- Keep-awake uses its own tag (`round-timer`), separate from the voice tag.
- The provider is added in `App.js` next to Session/Favorites/Voice, and `useTimerContext()`
  goes in `contexts/AppContext.js`.

### Settings (`hooks/useTimerSettings.js`, `data/timerPresets.js`)
- Mirrors `useFavorites`: AsyncStorage keys `@muaythai_timer_settings` and
  `@muaythai_timer_presets`.
- Defaults:
  - Muay Thai preset: 5 × 3:00, rest 2:00, lead-in 10 s;
  - clap at 10 s, rest double-beep at 10 s;
  - 3-2-1 beeps on, TTS on, vibrate off;
  - `trainingClock: 'center'`.

### Sound (`scripts/generate-sounds.js` → `assets/sounds/`, `hooks/useTimerCues.js`)
- **Generator.** A Node script with no dependencies writes 44.1 kHz 16-bit mono WAVs. It's
  committed and re-runnable. Each sound is normalized to about −1 dBFS, with short fades so
  nothing clicks.
  - `bell.wav`, a boxing bell strike (~2.8 s):
    - inharmonic bell partials (hum 0.5×, 1×, 1.19×, 1.5×, 2×, 2.74×, 3.76×, 5.4× of about
      740 Hz), each with its own exponential decay, so higher partials die faster;
    - detuned partial pairs for shimmer;
    - a 3 ms noise strike transient.
  - `bell-x3.wav`: three strikes 0.32 s apart, the classic "ding-ding-ding" end of round.
  - `clap.wav`: a wooden clapper. Two knocks 110 ms apart, each a band-passed noise burst plus
    damped ~0.9 / 2.1 kHz resonances.
  - `beep.wav`: a 1 kHz tick (120 ms) for 3-2-1.
  - `rest-warn.wav`: a double beep for the end of rest.
  - The user previews them on the Mac (`afplay`) before they ship. There's also an in-app
    "Test sounds" row.
- **Playback (expo-audio).**
  - One `createAudioPlayer` per sound, preloaded once. Each play does `seekTo(0)` then
    `play()`, because Context7 confirms `play()` doesn't rewind.
  - `setAudioModeAsync({ playsInSilentMode: true, interruptionModeAndroid: 'duckOthers', shouldPlayInBackground: false })`,
    so the user's music ducks under the bells.
- **expo-speech** handles TTS (`en-US`). Its start and done callbacks feed the voice echo guard.
- **Vibration** uses RN's built-in `Vibration`.
- New native dependencies: `npx expo install expo-audio expo-speech react-native-svg`. This
  needs **one new dev build**, right after step 1. Everything after that is JS over Metro.

### UI
- **`components/timer/TimerRing.js`.** The Timer-tab run face (D–I): an SVG ring plus big
  tabular digits, with phase colors.
- **`components/timer/TimerDial.js`.** The analog "gym clock" (N).
  - The wedge shows the time left, and a full circle equals the current phase.
  - The hand sweeps clockwise.
  - Ticks every 15 s, or every 5 s for phases of 60 s or less. The rim has a warning arc.
  - The hub shows the digits and a short line.
  - `size` prop.
- **`components/timer/TrainingClock.js`.** Rendered by `TrainingScreen` in both of its states
  (filters and session).
  - **Visible** while `status` is running or paused, or for 2 s after done. It fades in and
    out with `Animated` opacity.
  - **Center (K).**
    - An overlay below the pinned header and mic, above the tab bar, so the header and mic
      stay live.
    - Contents: phase label, 188 px dial, pause/skip/stop, and a **current-combo card**.
    - The card shows the expanded combo or the last-opened combo, with its description, heart
      and 60 s bar. ‹ › call `expandPrevious` / `expandNext`. Before any combo is open, it
      reads "Next up: combo 1". On the filter screen there's no card.
  - **Top (L)** is a band that replaces the title while running. **Bottom (M)** is a band above
    the tab bar, and the list gets bottom padding. In both, the current combo is the opened
    card in the list.
  - **Off** shows nothing on Training; the tab label still shows the time.
- **`hooks/useSession.js`.** Expose `activeIndex` as state, mirroring `activeSlotRef` in
  `activate()`. The card needs the last-opened slot reactively, and the ref stays for immediate
  reads by back-to-back voice commands.
- **Timer pill (J).** In the Training header on both states. Tap starts the saved workout, and
  long-press navigates to Timer.
- **Sheets** (RN `Modal` bottom sheets that share one shell):
  - `DurationSheet` (B): round time and rest. Min/sec steppers with hold-to-repeat, and quick
    chips.
  - `OptionSheet` (B2): round-end warning, rest-end warning and start delay, as chips.
  - `ClockPositionSheet` (B3): four schematic tiles.
  - `SavePresetSheet` (B4): name input. Deleting a custom preset is a long-press on its chip,
    confirmed with a native Alert.
- **`screens/TimerScreen.js`.** Setup (A–C) and run (D–I).
  - Setup (A, scrolling to A2) includes the "Test sounds" chips and the Display card
    ("Clock on Training").
  - The quick countdown run screen is E2.
  - The top-right mic pill on run screens toggles the mic.
  - While running, stop needs a long-press. While paused, one tap stops.
  - Controls are sized for gloves: 78 px main button, 54 px secondary buttons.
- **`constants/theme.js`.** Add `timerPrep/Work/Warn/Rest/Done`, reusing the existing chip hues
  (`#EF9F27`, accent, `#F0544F`, `#85B7EB`, `#97C459`).
- **`App.js`.**
  - Add the `Timer` tab with the Ionicons `timer-outline` icon.
  - The tab label reads from `TimerContext` and shows the live phase and time in the phase
    color.

### Voice
- **Split grammars.**
  - `voice/numbers.js` holds `WORD_TO_NUM`, extended to 0–60 plus tens compounds
    ("forty five"), "half" and "2:30".
  - `voice/comboGrammar.js` holds today's `parseCommands`, with unchanged behaviour.
  - `voice/timerGrammar.js` is new.
  - `useVoiceCommands` merges both parsers in spoken order, and each command carries
    `domain: 'combo' | 'timer'`.
- **Timer grammar** (wireframe section 6):
  - "set 2 minutes countdown" / "countdown 90 seconds" starts a quick one-off countdown;
  - "set 5 rounds of 3 minutes" starts that workout;
  - "set rest / rounds / round / delay …" edits one saved setting, idle only;
  - "preset <name>" loads a preset;
  - "timer start | pause | resume | skip | stop | reset" controls the run.
  - A bare "pause" or "stop" is ignored.
  - "set" is optional, because it's often misheard as "said" or "sit".
- **Firing rule.**
  - Duration and setting commands fire only on `isFinal`, so "2 minutes… 30 seconds" can
    finish. The 10 s lead-in hides the ~1 s latency.
  - Timer controls fire on interim results, the same way combo commands do.
- **Echo guard.**
  - `useVoiceCommands` gains `suppress(untilMs)`.
  - `useTimerCues` calls it while TTS speaks (+500 ms) and for about 1.5 s after each bell.
- **Global mic.**
  - `MicButton` renders on both Training states and on the Timer tab, with a `hint` prop for
    each place.
  - Remove `App.js`'s "stop mic when session not generated" effect. It only existed because
    the button disappeared.
- **Router** (`App.js` `onCommand`):
  - `timer` commands call `TimerContext` and return the confirmation line ("✓ 2:00 countdown").
  - On Training they stay put, and the Training clock shows the timer. From Favorites they
    switch to the Timer tab.
- Add the timer phrases to `contextualStrings`.

### Tests
Add `jest-expo` with pure-module tests only:
- `roundTimer` (segments, cues, positionAt, pause math);
- `timerGrammar`, using the mishearing tables;
- `comboGrammar` (a regression net for the refactor).

## Design fidelity contract

The user requires **the built UI to match the wireframes exactly**. The wireframes file is the
visual spec, and this plan is the behaviour spec.

- **Don't redesign.** If something can't be built as drawn, stop and ask the user. Once they
  agree, update the wireframe first, then write the code.
- **Scope of the match.**
  - Every *new* element must match: the Timer tab (A–I), the timer pill, the Center overlay and
    current-combo card, the Top/Bottom bands, the dial, the ring and the tab label.
  - Existing UI drawn in J–M (combo cards, New session, MicButton styling) is approximate.
    Keep the current code for those.
  - Only the new MicButton hint copy comes from the wireframes.
- **Copy.** Every new user-visible string (labels, hints, uppercase phase labels, confirmation
  lines, TTS lines, button text) must be character-for-character as in the wireframes.
  Wireframe sample data (combo names, times) is not copy.
- **Colors.** Use only the wireframe `:root` tokens: `constants/theme.js` plus the five timer
  tokens. Add these wireframe literals as named theme tokens too:
  - overlay `rgba(12,12,12,.93)`;
  - band `#151515`, sheet `#181818`;
  - dial face `#141414` with `#2e2e2e` stroke, and hub `#0f0f0f`;
  - ring track `#202020`;
  - the phase tint gradients (`.tint-prep/-warn/-rest`);
  - chip-on `rgba(232,108,58,.14)`;
  - paused ring `#5a5a5a`.
- **Units.** Wireframe CSS px map to RN dp 1:1 for font sizes (including 12.5), weights,
  paddings, gaps, radii, borders and control sizes: main 78, secondary 54, mini 34, nav ‹ › 30,
  steppers 22 and 40×32, toggle 30×17. Widths flex.
  - The wireframe phone content is 286 px wide, so two sizes scale with the real content
    width `W`: the run ring `236·W/286` and the Center dial `188·W/286`. Their inner text
    scales by the same factor.
  - The Top and Bottom band dials (112 and 104) stay fixed.
- **Type.** System font (Roboto). Keep the wireframe weights: ring digits 300, lead-in 104 px
  digits 200, dial digits 500. Timer numbers use `fontVariant: ['tabular-nums']`.
- **Geometry.** Port the wireframe's `svg.dial` renderer (the `<script>` at the bottom of the
  HTML) into `TimerDial` 1:1:
  - viewBox 200, rim r 98 (stroke 2), wedge R 90;
  - warning arc r 95 (width 5, round caps);
  - ticks 16/8 long, 3.5/2 wide, at 0.85/0.45 opacity;
  - hand width 4.5, reaching R+3;
  - hub r 44 (26 in the bands);
  - digits 34 at y 108 (112 without a sub line), sub line 13 at y 131;
  - tick step 15 s (5 s if the phase is ≤ 60 s, 30 s if it's over 180 s).

  The ring uses viewBox 220, r 100, stroke 12 with round caps. It starts at 12 o'clock and
  shows the time left.
- **Tab label rule.**
  - On the Timer tab it shows the time only ("2:47").
  - On other tabs it shows `R{n} · m:ss` during a round, `Rest · m:ss` during rest, and `m:ss`
    during the lead-in or a countdown.
  - Paused adds a `❚❚ ` prefix. The label takes the phase color.
- **Timer pill.** Shown on Training only while the timer is idle.
- **Wireframe-only artifacts (don't build):**
  - annotation pins, notes, status bar and bezel;
  - `.fade` scroll hints;
  - the chip-row edge mask. A plain horizontal `ScrollView` is enough.
- **Verification** after every UI task:
  - capture a device screenshot for each affected frame in the same state and compare it
    side by side with the wireframe;
  - run the `wireframe-vs-code` agent for functional gaps;
  - fix every difference, or get the user's explicit sign-off on it.
